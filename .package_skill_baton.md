## Test rig policy change (2026-09-28, Donald's instruction)
**Relaunch the portable fresh before EACH package test, check its console immediately (clean baseline), then test.** Don't accumulate one long-running console history across many packages -- it makes attributing a given error to the right package error-prone (caught a case where a stale/frozen Tab-1 paste looked "clean" for several turns running because nothing had actually re-pasted it).

**Read the portable's console yourself -- don't ask Donald to copy-paste.** The portable's own HTTP bridge (`/console` on :9510) is slow enough (full visible-console capture) that it reliably triggers the claude-code false-interrupt bug (rejected tool_use, claude-code#93529) -- confirmed the trigger is latency-based (~0.9s+), not tool-specific: it hit Bash, computer-use, AND mcp__sublime-mcp__eval_python identically. The fix: use the FAST endpoint instead -- relay through the REAL ST's own `eval_python` (`mcp__sublime-mcp__batch`, not Bash, not computer-use) calling the portable's `/console_log?tail=N` route (captured/ring-buffer mode, not the slow full capture):
```python
import urllib.request, json
r = json.load(urllib.request.urlopen('http://127.0.0.1:9510/console_log?tail=200', timeout=5))
print(r.get('text', r))
```
This returns instantly and hasn't been hit by the false-interrupt bug once. Use this after every install/test instead of asking for a manual paste.
